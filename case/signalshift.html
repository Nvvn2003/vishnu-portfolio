The Problem

Creators post blind.

Every serious content creator faces the same three problems — and there was no single tool solving all of them.

Problem 01
Algorithm Blindness
When engagement drops, creators can't tell if it's their content, an algorithm shift, or random variance. Without a diagnosis, any response is guesswork.
Problem 02
Siloed Trend Intelligence
Trending topics are scattered across Reddit, X, Google Trends, and news sites — all requiring separate visits, with no synthesis or regional depth.
Problem 03
Generic Content Advice
"Post consistently" is not advice. Creators need format-specific hooks for their niche — not platform-generic tips that apply to everyone and help no one.
The Inspiration

The GCI for social media.

I found the idea by studying gulfcorridorindex.com — a real-time intelligence dashboard for Strait of Hormuz shipping traffic. It monitors corridor health via composite signals, fires threshold alerts, and gives operators a 0–100 score to act on.

💡
I asked: what other domains have opaque, high-stakes, signal-detectable shifts? Social media algorithms. They change silently, cut creator reach overnight, but are traceable via engagement data, community complaint spikes, and platform changelogs — exactly like shipping corridor risk is traced via vessel positions and geopolitics.
Algorithm Health Monitor

A score for every platform, in real time.

Each platform gets a composite score (0–100) built from four independent signals. Scores update every 30 minutes and trigger alerts when thresholds are crossed.

Build Process

4 weeks, start to finish.

From analyzing a shipping intelligence dashboard to a full-stack social media intelligence product.

Week 1
Research & Concept Definition
  • Analyzed gulfcorridorindex.com: UX patterns, scoring model, alert architecture
  • Mapped GCI concept to social media: corridor health → algorithm health
  • Defined scope: 5 platforms, all 3 user types, freemium model, real data from day 1
  • Designed 4-signal scoring architecture with weights before writing any code
Week 2
Full-Stack V1 Build (37 Files)
  • Scaffolded Next.js 14 App Router project with TypeScript + Tailwind
  • Built auth: NextAuth.js credentials provider + bcrypt + SQLite users table
  • Implemented scoring engine (lib/scoring/index.ts) with all 4 signals
  • Wired Google Trends + Reddit APIs; built /api/signals, /api/trending, /api/alerts routes
Week 3
Interactive Demo — 6 Iterations
  • Built self-contained HTML/JS widget (no build step, no server required)
  • V1–V3: Dashboard with animated SVG score rings and platform status
  • V4: Trends tab added — hit token limit, full rebuild required
  • V5: Rebuilt with compact data format; V6: Final with all features
Week 4
Feature Expansion
  • India region: 10 dedicated topics (cricket, Bollywood, NRI, startup stories, shaadi, street food)
  • PFMT engine: 4 formats × 3 hook ideas per platform — 60+ content angles per trend
  • Niche personalization: free-text input rewrites all content angles through creator's lens
  • Weekly master plan: 7 topics × 1 per day, best platform auto-selected by score
Product Decisions

Every choice was deliberate.

The best decisions were the ones about what not to build. Here are the most important trade-offs in V1.

All 5 platforms at once
Algorithm shifts on one platform often precede or correlate with others. Cross-platform intelligence is the core value proposition — starting with one would undercut the entire product.
Real APIs, zero mocks
Mocked data destroys demo credibility for a product whose core claim is "real-time intelligence." Google Trends and Reddit JSON both work without API keys — there's no excuse for fake data.
India as dedicated region
India's creator economy is the fastest-growing globally. Cricket, Bollywood, NRI culture, and shaadi content are categorically different from APAC averages — lumping them together makes trend data useless for Indian creators.
SQLite for V1
Zero config, embedded, same query logic migrates to Postgres in V2. Over-engineering the database before proving the product is a classic mistake.
